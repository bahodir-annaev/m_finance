# MIZAN Finance v5 — Руководство пользователя

**Версия 5.0 · English version: [USER_MANUAL.md](USER_MANUAL.md)**

Это руководство описывает повседневную и ежемесячную работу в MIZAN Finance v5.
Оно рассчитано на двух читателей: на того, кто вводит документы и закрывает период,
и на руководителя, которому важно понимать, из чего складывается себестоимость часа.

Программа работает на трёх языках (O'zbekcha, Русский, English). Здесь приводятся
**русские** названия — те же, что в интерфейсе. Полный трёхъязычный глоссарий — в
[§39](#39-справочник). Нумерация разделов совпадает с английской версией: §14.3 означает
одно и то же в обоих файлах.

# Часть I — Начало работы

## 1. Что это за программа

MIZAN Finance v5 — локальная офлайн-программа для финансового учёта архитектурного бюро.
Она работает на одном компьютере, хранит всё в одном файле и доступна только из локальной
сети. Никаких облачных сервисов и подключения к интернету не требуется.

**Её задача — рассчитать, во сколько бюро реально обходится один час работы каждого
производственного сотрудника.** Всё остальное существует ради того, чтобы этой цифре
можно было доверять.

Это стоит сказать прямо, потому что программа выглядит как бухгалтерская система — и
является ею: она ведёт полноценный двойной учёт по национальному плану счетов
(НСБУ №21). Но учёт здесь не цель. Цель в том, чтобы когда программа показывает
себестоимость архитектора 92 400 сум в час, эта цифра была собрана из фактически
выплаченных зарплат, фактически понесённых накладных расходов и фактически купленного
оборудования — а не из чисел, которые кто-то вписал в таблицу год назад и с тех пор не
трогал.

Из этой одной цифры выводится всё остальное, что нужно бюро для прибыльной работы:
ставка продажи, себестоимость проекта, рентабельность, лестница цен для нового
предложения и сравнение плана с фактом по текущим объектам.

### Чем это отличается от v4

Если вы работали в MIZAN v4, три вещи изменились принципиально:

| | v4 | v5 |
|---|---|---|
| **Как фиксируются деньги** | Строка транзакции с полями «сумма» и «оплачено» | Документ, который порождает сбалансированную двойную проводку |
| **Откуда берутся накладные** | Таблица, заполняемая вручную | Учёт — что реально потрачено, усреднённое за скользящее окно |
| **Как платёж закрывает счёт** | Правкой поля «оплачено» | Отдельным документом платежа, *распределённым* на счёт |

v4 остаётся установленной и работает. У неё другой файл базы (`mizan_finance.db`) и
другой порт, поэтому обе программы могут быть открыты одновременно. База v5 — `mizan5.db`.
Ничто из того, что вы делаете в v5, не затрагивает v4.

Если бюро действительно переходит на v5, см. [§35](#35-разовый-перенос-из-v4) — есть
разовый перенос, который проигрывает всю историю v4 в v5.

## 2. Установка и запуск

### Требования

Python 3.10 или новее, с установленными Flask и openpyxl:

```bash
pip install flask openpyxl
```

### Запуск

Из каталога `mizan5`:

```bash
python app.py
```

Программа находит порт (5000, если свободен, иначе любой свободный), печатает баннер и
примерно через полторы секунды сама открывает браузер:

```
==================================================
  MIZAN Finance v5.0
  http://127.0.0.1:5000
  To'xtatish: Ctrl+C
==================================================
```

Для остановки нажмите `Ctrl+C` в этом окне. Останавливайте программу осознанно, а не
закрывайте окно, пока кто-то работает, — чтобы запись не прервалась на середине.

### Первый запуск

При самом первом старте программа создаёт базу и одну учётную запись администратора,
после чего **один раз** печатает пароль:

```
Admin foydalanuvchisi yaratildi / Admin user created
    login:  admin
    parol / password:  kX8vQ2mN4pR7
Bu parol faqat bir marta ko'rsatiladi.
```

**Запишите его прежде, чем закроете это окно.** Пароль нигде не хранится в читаемом виде
и не может быть восстановлен — если он потерян, единственный путь обратно — удалить базу
и начать заново. Проблемы можно избежать, задав пароль заранее через
`MIZAN_ADMIN_PASSWORD` (см. ниже).

После входа создайте реальные учётные записи — [§31](#31-пользователи-и-роли).

### Переменные окружения

Все необязательные. Задайте их в командной строке перед `python app.py` либо запишите в
файл `.env` рядом с `app.py` строками вида `КЛЮЧ=значение`. Настоящие переменные окружения
всегда важнее файла `.env`.

| Переменная | Что делает |
|---|---|
| `PORT` | Жёстко задать порт. `PORT=5177 python app.py` |
| `MIZAN_NO_BROWSER` | `1` — не открывать браузер автоматически |
| `MIZAN_ADMIN_PASSWORD` | Задать первый пароль администратора вместо случайного. Действует только на базе, где ещё нет пользователей |
| `MIZAN_SECRET_KEY` | Ключ подписи сессий. Если не задан, генерируется и хранится в `.mizan5_secret_key`. Смена ключа разлогинивает всех |
| `MIZAN5_DB` | Другой файл базы. Удобно для тестовой копии: `MIZAN5_DB=test.db python app.py` |

### Кто может подключиться

Программа отклоняет любое подключение не из локальной сети. Разрешены адреса, начинающиеся
на `127.` (этот компьютер), `192.168.`, `10.` и `172.`. Всё остальное получает:

```
Access denied: this app is only available on the local network.
```

Сервер к тому же слушает только `127.0.0.1`, то есть по умолчанию доступен **только с
этого компьютера**. Чтобы дать доступ коллегам по офисной сети, привязку нужно изменить
осознанно — случайно это не произойдёт, и делать это стоит, подумав, кто ещё есть в этой
сети.

### Где лежат данные

Всё в одном файле: **`mizan5.db`**, в каталоге `mizan5`. Счета, документы, проводки,
сотрудники, проекты, настройки — всё. Скопировали этот файл — скопировали всю систему.
См. [§36](#36-резервное-копирование).

## 3. Вход, язык и права доступа

### Вход

Открывается карточка входа: **Пользователь** и **Пароль**, затем **Вход**. При ошибке
показывается *Неверный логин или пароль* — программа не уточняет, что именно неверно.
Отключённый пользователь не войдёт даже с правильным паролем.

### Язык

Три языка, переключаются в любой момент и запоминаются на год в куки браузера:

- На **странице входа** — три ссылки под формой: `UZ · RU · EN`
- После входа — **внизу боковой панели**, рядом с именем пользователя

По умолчанию узбекский. Переключение меняет только то, что вы видите; данные не
затрагиваются, и два человека могут одновременно работать на разных языках.

### Роли

У каждого пользователя одна из трёх ролей. Они накопительные: менеджер может всё, что
наблюдатель, а администратор — всё, что менеджер.

| Роль | Название | Что может |
|---|---|---|
| `viewer` | Наблюдатель | Читать все страницы и отчёты. Ничего не создаёт, не изменяет, не проводит и не удаляет. |
| `manager` | Менеджер | Всё вышеперечисленное плюс вся обычная работа: ввод и **проведение** документов, удаление черновиков, контрагенты, сотрудники, зарплаты, табель, оборудование, лицензии, накладные, проекты, этапы, займы; расчёт и выплата зарплаты; ввод курсов валют; фиксация ставок за период. |
| `admin` | Администратор | Всё вышеперечисленное плюс всё необратимое и структурное: **сторно** проведённого документа, **закрытие и открытие периодов**, проведение амортизации и переоценки валюты, правка плана счетов и настройки проводок, сроки службы по классам активов, переклассификация оборудования, база расчёта ставок, параметры программы, пользователи и справочники. |

Разделение сделано намеренно. Повседневный ввод данных — работа менеджера. Всё, что
переписывает историю (сторно проведённого документа), замораживает её (закрытие периода)
или меняет способ расчёта всех цифр в бюро (счета, база расчёта ставок), — работа
администратора.

Попытка действия выше своего уровня возвращает **403 — Ruxsat yo'q** (*Доступ запрещён*).
Ничего не ломается; нажмите «Назад».

### Как устроен любой список

Освоив один список, вы освоили все. У них общая раскладка:

```
+----------------------------------------------------------+
|  Заголовок                                    [ Создать ] |
+----------------------------------------------------------+
|  С [____] По [____] Статус [___] Поиск [___]  Фильтр      |
+----------------------------------------------------------+
|  Дата   Номер   Контрагент   Сумма   Статус          (/)  |
|  ...                                                      |
|  Итого                        123 456                     |
+----------------------------------------------------------+
```

- **[Создать]** справа сверху открывает диалог новой записи.
- **Карандаш** в конце строки открывает *тот же* диалог, заполненный этой строкой.
- **Фильтр** применяет условия, **Сбросить** очищает их. Фильтры живут в адресной строке,
  поэтому отфильтрованный вид можно сохранить в закладки или отправить коллеге.
- Большинство таблиц заканчивается строкой **Итого** по показанным строкам — то есть по
  отфильтрованному набору, а не по всей таблице.
- Списки документов **постраничные** (25 / 50 / 100 / 200 строк, выбирается внизу таблицы)
  и **сортируемые** — щёлкните по заголовку столбца, второй щелчок меняет направление.
  Номер страницы, сортировка и размер страницы тоже живут в адресной строке. Списки
  документов дополнительно фильтруются по **контрагенту**, **проекту** и
  **ответственному**, а поиск заглядывает в примечания и названия проектов.

Внутри диалога всё обычно: заполнили, нажали **Сохранить**, страница перезагрузилась с
подтверждением или ошибкой сверху. Автосохранения нет; по **Отмена** или `Esc` ничего не
сохраняется.

### Табличные части

В диалогах документов внизу есть табличная часть — строки счёта, распределение платежа,
строки зарплаты, дебет и кредит проводки. Все они работают одинаково:

- **[Добавить строку]** добавляет строку, **✕** в строке удаляет её.
- Итоги под таблицей пересчитываются по мере ввода: без НДС, НДС, с НДС, распределено,
  не распределено, дебет, кредит.
- В ручной проводке и начальных остатках под таблицей показывается, сошлись ли дебет с
  кредитом. **Пока не сошлись, кнопка сохранения заблокирована.** Программа не даст
  собрать несбалансированную проводку — через эту форму учёт сломать нельзя.

### Галочка «Провести»

Внизу каждого диалога документа есть галочка **Провести**, и она **установлена по
умолчанию**. Оставленная включённой, она сохраняет документ *и* сразу записывает его в
учёт. Почти всегда именно это и нужно.

Снимите её, чтобы сохранить **черновик**: документ сохранён, доступен для правки и ни в
один отчёт не попадает. См. [§5](#5-документы-становятся-проводками).

# Часть II — Что нужно понять до начала работы

Эти шесть разделов короткие, и один раз их прочитать стоит: v5 ведёт себя иначе, чем v4,
причём различия не видны на экране.

## 5. Документы становятся проводками

Проводки вручную вы не пишете. Вы вводите **документы** — счёт, поступление, платёж — а
программа выводит из них бухгалтерию:

```
   Вы заполняете диалог
            |
            v
   Сохраняется документ           <- это ещё можно править
            |
            v
   Правило проводки строит дебет и кредит
            |
            v
   Проводка проверяется и записывается в учёт
            |
            v
   Все отчёты — это выборки из учёта
```

Поскольку каждый отчёт читает только учёт, непроведённый документ не виден ни в одном
отчёте.

### Три состояния

| Состояние | Название | Что означает |
|---|---|---|
| `draft` | Черновик | Сохранён, но не в учёте. Можно править и удалять. Ни в одном отчёте не виден. |
| `posted` | Проведён | В учёте. **Править нельзя.** Виден везде. |
| `void` | Сторнирован | Был проведён, затем отменён зеркальной проводкой. |

### Почему проведённый документ нельзя изменить

Это главное отличие от v4 и то, обо что спотыкаются первым делом.

В v4 можно было открыть транзакцию и поменять сумму. В v5 нельзя, и программа прямо об
этом говорит:

> *Проведённый документ нельзя изменить — сторнируйте его*

Причина в том, что документ больше не единственная запись о случившемся. Существует
проводка — с датой, номером, в месяце, который, возможно, уже закрыт, — питающая
оборотно-сальдовую ведомость, которую кто-то уже смотрел. Тихая правка документа под всем
этим привела бы к тому, что учёт перестал бы сходиться сам с собой.

**Чтобы исправить проведённый документ:** нажмите **Сторнировать**, укажите причину и
введите новый, правильный документ. Оба останутся видны. Это не мусор, а преимущество:
история исправлений и есть аудиторский след, и именно её ожидает увидеть проверка.

### Что именно делает сторно

Сторно ничего не удаляет. Оно записывает вторую проводку — точное зеркало первой: каждый
дебет становится кредитом на ту же сумму и тот же счёт, с теми же проектом, контрагентом
и сотрудником. Пара взаимно уничтожается на любом счёте, в любом отчёте, на любую дату.
Оригинал остаётся в журнале с пометкой, зеркало помечено как *Сторно*.

Сторнировать документ можно только один раз. Это действие **уровня администратора**.

### Удаление

Удалить можно только **черновик**, и он удаляется полностью. Проведённый документ удалить
нельзя никогда — только сторнировать. Полностью убрать проведённый документ из записей
программа не позволит, и это сделано намеренно.

## 6. План счетов без теории

Программа поставляется с национальным планом счетов (НСБУ №21). Учить его не нужно. В
повседневной работе вы встретите десятка два счетов, и почти все программа подставит сама.

### Четыре вида

У каждого счёта есть **Вид**, который определяет его нормальную сторону:

| Вид | Название | Простыми словами | Растёт по |
|---|---|---|---|
| **А** | Актив | То, чем бюро владеет или что ему должны: деньги, дебиторка, оборудование | Дебету |
| **КА** | Контрактив | Вычет из актива — вам встретится только накопленная амортизация | Кредиту |
| **П** | Пассив | То, что бюро должно: поставщикам, сотрудникам, бюджету, по займам; и капитал собственников | Кредиту |
| **Т** | Транзакционный | Доходы и расходы. Закрываются на финансовый результат в конце периода | По типу |

Практическое следствие одно: в балансе счета А показаны как актив, П — как пассив и
капитал, КА — как вычет в скобках. Счета Т попадают не в баланс, а в отчёт о прибылях и
убытках, и каждый год начинают с нуля.

### Счета, которые встретятся на практике

| Код | Что на нём | Откуда берётся |
|---|---|---|
| **5110** | Расчётный счёт (сум) | Приход и расход через банк |
| **5010** | Касса | Приход и расход наличными |
| **5210** | Валютный счёт | Любой документ в валюте, отличной от сума |
| **4010** | Дебиторка — что должны заказчики | Счета-фактуры выданные |
| **6010** | Кредиторка — что должны вы | Счета-фактуры полученные |
| **6310** | Авансы полученные | Платёж заказчика без счёта |
| **4310** | Авансы выданные | Платёж поставщику без счёта |
| **6410.1** | НДС начисленный | Счета-фактуры выданные |
| **4410** | НДС к зачёту | Счета-фактуры полученные |
| **6710** | Расчёты по оплате труда — сумма к выплате | Начисление зарплаты |
| **6420.1** | НДФЛ удержанный (JSHDS) | Начисление зарплаты |
| **6520** | Социальный налог к уплате | Начисление зарплаты |
| **2010** | Основное производство — прямые затраты по проекту | Зарплата производственных сотрудников; закупки с проектом |

| **9420.1** | Расходы на амортизацию | Ежемесячное начисление амортизации |
| **9420.2** | Административный персонал | Зарплата АУП |
| **9420.3** | Лицензии и ПО | Стоимость лицензий |
| **9910** | Финансовый результат | Закрытие периода |
| **0000** | Вспомогательный — только для начальных остатков | Документ начальных остатков |

Три субсчёта 9420 — **9420.1, 9420.2 и 9420.3** — существуют по одной конкретной причине,
описанной в [§9](#9-правило-двойного-счёта). Не меняйте их настройки, не прочитав его.

### Назначения, а не коды

Ни в одном месте логики программы не зашит код счёта. Каждое правило проводки запрашивает
**назначение** — «счёт дебиторки», «расчётный счёт», «счёт выручки», — а таблица
сопоставляет назначения с реальными счетами.

Эта таблица — на странице `/accounts`, в карточке **Проводка → Счёт**. Благодаря ей бюро
может перенаправить любое назначение на другой счёт, не трогая код. Если движения по банку
должны идти на другой счёт учёта, вы меняете это один раз, и все последующие проводки идут
туда. Если же за одним кодом 5110 у бюро стоит *несколько* реальных счетов в банке — это не
переназначение: зарегистрируйте их на `/bank-accounts` ([§15](#15-списание-денег)).

## 7. Погашение — это распределение, а не галочка

В v5 нет поля «оплачено». Никакая галочка не помечает счёт закрытым.

Вместо этого: счёт — один документ, платёж — другой, и вы **распределяете** платёж на
счёт. Остаток по счёту — это его сумма минус всё, что на него распределено.

```
   Счёт-фактура SF-2026-00042        12 000 000
        ^                     ^
        |                     |
   PK-...-00113  5 000 000    |          остаток 7 000 000
   PK-...-00131  7 000 000 ---+          остаток 0
```

Звучит как больше работы, чем правка колонки «оплачено», и при одном полном платеже это
действительно на пару кликов дольше. Взамен вы получаете:

- **Один платёж может закрыть несколько счетов.** Заказчик переводит 30 миллионов по
  четырём счетам; вы вводите одно поступление и делите его на четыре. В v4 это было четыре
  отдельных правки, и банковская выписка уже ни с чем не сходилась.
- **У каждого платежа своя дата, способ и валюта.** Частичные платежи не затирают друг
  друга.
- **Отчёт о движении денег становится настоящим.** Каждое поступление видно в тот день,
  когда оно пришло.

### Куда уходит нераспределённое

В диалоге видна текущая сумма **Не распределено**. То, что останется при сохранении,
должно куда-то попасть, и программа решает так:

| Ситуация | Куда уходит остаток |
|---|---|
| Приход, контрагент указан | **6310** — аванс полученный |
| Расход, контрагент указан | **4310** — аванс выданный |
| Приход, контрагент не указан | **9390** — прочие операционные доходы |
| Расход, контрагент не указан | **9430** — прочие операционные расходы |

Вариант с авансом нормален и корректен: заказчик, заплативший до выставления счёта,
действительно имеет предоплату, и она закроется, когда вы выставите счёт и распределите
на него этот аванс.

Вариант без контрагента — аварийный, а не рабочий. Если поступления регулярно попадают на
9390, значит кто-то пропускает поле контрагента. Счета 9390 и 9430 намеренно разные: 9430
входит в пул накладных расходов, а 9390 нет, поэтому неопознанный *приход*, попавший на
9430, вычел бы сам себя из накладных и тихо снизил бы себестоимость часа у всех.

### Что программа не даст сделать

- Распределить больше суммы платежа.
- Распределить больше остатка по счёту.
- Распределить на **непроведённый** счёт — у черновика нет остатка, который можно
  закрыть.

## 8. Из чего складывается себестоимость часа

Это та самая цифра, ради которой существует программа. Стоит понимать, что в неё входит:
если значение на `/rates` выглядит неправильным, причина всегда в одном из этих исходных
данных.

### Доступные часы

```
доступные часы = (365 - 104 выходных - праздники - отпуск) / 12 * 8
```

При 14 праздничных днях и 20 днях отпуска и болезней по умолчанию это примерно
**151 час в месяц**, или 1 816 в год. Это попадает в диапазон 1 760–1 880, который
используется в международной проектной практике.

Это не 176 часов. Расчёт по 176 — двенадцать месяцев по 22 рабочих дня — предполагал бы,
что никто никогда не отдыхает, и занижал бы себестоимость часа примерно на 15%.

### Из чего складывается месячная стоимость сотрудника

По каждому производственному сотруднику складываются восемь составляющих, и результат
делится на доступные часы:

| Составляющая | Что это | Ведётся на странице |
|---|---|---|
| Оклад с премией | База + премия | `/staff` |
| Налог | НДФЛ с начисленного | `/settings` (`tax_rate`) |
| Соцналог | Социальный налог работодателя | `/settings` (`social_rate`) |
| Доля АУП | Его доля во всех административных зарплатах | `/staff` (административные сотрудники) |
| Личное оборудование | Его компьютер, монитор, стол — месячная амортизация | `/staff/equipment` |
| Личные лицензии | Его Revit, 3ds Max и прочее — годовая стоимость ÷ 12 | `/staff/equipment` |
| Доля общего оборудования | Его доля в общих принтерах, серверах, мебели | `/staff/equipment` |
| Доля накладных | Его доля в аренде, коммунальных и прочих косвенных расходах | Учёт или `/staff/equipment` |

```
себестоимость часа = месячная стоимость / доступные часы
ставка продажи     = себестоимость часа x наценка       (по умолчанию 2,0)
```

Наценка — один множитель, покрывающий и недозагрузку (никто не продаёт 100% доступных
часов), и целевую маржу. Больше маржа нигде не добавляется; добавить её ещё раз означало
бы посчитать её дважды.

### Четыре общих расхода

Административные зарплаты, общее оборудование и накладные нельзя отнести на одного
человека, поэтому они распределяются по производственным сотрудникам. База по умолчанию —
**прямая оплата труда**: ведущий архитектор с большей зарплатой принимает на себя
пропорционально больше накладных, чем младший. Альтернативная база — **оплачиваемые часы**,
как это было в v4.

В любом случае доли всегда дают в сумме ровно единицу — каждый сум накладных расходов
отнесён на кого-то. Ничего не остаётся невозмещённым.

Базу выбирают на `/rates` — см. [§23](#23-себестоимость-часа).

## 9. Правило двойного счёта

**Это самое важное предупреждение в руководстве.** Оно касается одной настройки на одной
странице, и ошибка в ней завышает всю себестоимость, все ставки продажи и все цены,
которые бюро называет заказчику, — при том что на экране ничто не выглядит сломанным.

### Ситуация

Часть расходов попадает в себестоимость часа через **регистр** — заполняемый вручную
список, который движок расчёта читает напрямую:

| Регистр | Страница | Что питает |
|---|---|---|
| Оборудование | `/staff/equipment` | Амортизацию личного и общего оборудования |
| Сотрудники и зарплаты | `/staff` | Долю АУП |
| Лицензии | `/staff/equipment` | Личные лицензии |

Те же самые расходы *одновременно* являются настоящими расходами, и учёт проводит их как
расходы: амортизацию на 9420.1, административную зарплату на 9420.2, лицензии на 9420.3.

При этом пул накладных расходов строится суммированием всех счетов с признаком
**Косвенные** (`cost_pool = indirect`) и распределяется по производственным сотрудникам.

### Само правило

> **Счёт не должен иметь признак «Косвенные», если тот же расход уже начисляется из
> регистра.**

Иначе расход будет посчитан дважды: один раз регистром, второй — через долю накладных, и
ничто нигде это не компенсирует. Все ставки просто окажутся завышенными.

### Как это выглядит на практике

Три счёта поставляются с признаком **Не учитывается** (`Hisobga olinmaydi`) именно поэтому:

| Счёт | Регистр, который уже его начисляет | Эффект при ошибочном признаке «Косвенные» |
|---|---|---|
| **9420.1** Амортизация | Регистр оборудования | Один ноутбук за 15 млн сум поднял себестоимость часа владельца с 73 744 до 93 018 — **+26%** |
| **9420.2** Зарплата АУП | Регистр сотрудников | На реальных данных бюро (27 производственных, 11 административных): +183 млн сум в месяц в пуле, **+13% ко всем ставкам** |
| **9420.3** Лицензии | Регистр лицензий | Растёт вместе с парком лицензий |

**«Не учитывается» не значит «проигнорировано».** Расход учтён полностью — просто через
свой регистр, а не через пул. Признак говорит лишь: *не считать его здесь второй раз*.

### Три защиты

О них полезно знать:

1. Программа **отказывается проводить** амортизацию, зарплату АУП или лицензии на счёт с
   признаком «Косвенные». Вы получите:
   > *Этот счёт входит в накладной пул — расход уже начисляется из своего регистра и будет
   > учтён дважды*
2. При каждом запуске программа **возвращает** этим трём счетам признак «Не учитывается».
3. Автотесты падают, если проведение амортизации или зарплаты сдвигает хоть одну ставку
   хотя бы на сум.

Сломать правило надолго трудно. Но в промежутке между правкой и перезапуском ставки на
экране будут неверными, и ничто не будет выглядеть сломанным.

### Единственная незакрытая брешь

Оборудование, купленное по счёту-фактуре полученному, списывается на **9420** — который
*входит* в пул, — в то время как регистр оборудования амортизирует тот же актив в те же
ставки. Это тот же двойной счёт, зашедший с другой стороны.

Программа это обнаруживает и предупреждает на `/rates`:

> *Некапитализированное оборудование (нет на 0150)*

Исправление ручное: вводя счёт на оборудование, укажите в строке счёт **0150** (или другой
счёт актива для его класса) вместо значения по умолчанию. См.
[§14](#14-счёт-фактура-полученный).

## 10. Периоды

Каждый месяц — это **отчётный период**, создаваемый автоматически при первой проводке в
него. У него одно из трёх состояний:

| Состояние | Название | Значение |
|---|---|---|
| `open` | Открыт | Обычное. Проводить можно что угодно. |
| `soft_closed` | Мягко закрыт | Новые проводки не принимаются. По смыслу обратимо. |
| `hard_closed` | Жёстко закрыт | Новые проводки не принимаются. Обычное финальное состояние. |

Оба закрытых состояния отклоняют проводки одинаково:

> *Период закрыт — проводка невозможна*

Это относится и к проводкам **задним числом**. Если март закрыт и вы пытаетесь ввести
документ с мартовской датой, он будет отклонён — в этом весь смысл. Закрыть месяц значит,
что отчётные цифры за этот месяц больше не изменятся.

### Открыть, подписать и удалить период

Периоды появляются сами, когда документ проводится в новый месяц. **[+ Период]**
открывает период заранее (подставляется следующий месяц). В каждой строке есть поле
примечания — однострочная памятка вроде *закрыт после аудита*, — сохраняется галочкой.
Открытый период **без проводок** удаляется кнопкой **×**; период с проводками — нет.

Список также показывает, насколько полно закрытие: сколько снимков ставок сотрудников
записано и сколько строк табеля проштамповано ставкой против всех строк месяца.

### Мягкое и жёсткое закрытие

**[Мягкое закрытие]** блокирует месяц и снимает ставки, но его можно снова открыть с этой
страницы. **[Закрыть период]** — жёсткое закрытие: делает всё то же и является
**окончательным** — интерфейс его не откроет. Исправление в жёстко закрытом месяце —
сторно-проводка в открытом месяце, что сохраняет отчётные цифры того месяца ровно
такими, какими они были отчитаны.

### Что происходит при закрытии месяца

Закрытие выполняет последовательность действий, и порядок здесь важен:

1. Проводит **амортизацию** за месяц, если она ещё не проведена.
2. Читает **отчёт о прибылях и убытках** за месяц.
3. **Фиксирует ставки** за месяц, рассчитанные по состоянию на последний день месяца, а не
   на сегодня. Закрытие марта в августе зафиксирует мартовские зарплаты, мартовское окно
   накладных и мартовское оборудование.
4. Записывает **проводку закрытия**: все счета доходов и расходов закрываются на **9910**,
   финансовый результат, где и остаётся прибыль или убыток месяца.
5. Помечает период закрытым.

После этого все счета вида Т начинают следующий месяц с нуля, а результат месяца лежит на
9910.

Закрытие и открытие — действия **уровня администратора**, на странице `/periods`. Полная
процедура закрытия месяца — [§27](#27-чек-лист-закрытия-месяца).

**[Создать]**, затем:

## 14. Счёт-фактура полученный

**Где:** боковая панель → Документы → **Счета-фактуры (полученные)**
(`/documents/purchase_invoice`)

Счёт, который выставляет вам поставщик: аутсорсинг, материалы, услуги, оборудование.

### Ввод

Устроен так же, как счёт выданный, только вместо покупателя — **Поставщик**. Поставщик и
хотя бы одна строка обязательны.

**Главное решение здесь — на какой счёт попадёт строка.** Если оставить счёт строки
пустым, программа выберет сама:

| Строка | Счёт по умолчанию | Смысл |
|---|---|---|
| С указанным **проектом** | **2010** Основное производство | Прямые затраты проекта. Попадают в его себестоимость и рентабельность. |
| **Без** проекта | **9420** Административные расходы | Накладные. Попадают в косвенный пул и распределяются на всех производственных сотрудников. |

Чаще всего это правильно. Есть два случая, когда нужно переопределить счёт вручную:

**Покупка оборудования.** Если счёт за ноутбук, монитор, стол — за что-либо, что вы также
внесёте в регистр оборудования, — укажите в строке счёт **0150** (компьютерное
оборудование) или правильный счёт актива для его класса. Если оставить значение по
умолчанию, ноутбук будет списан на 9420 *и* самортизирован через регистр оборудования, и
его стоимость попадёт в себестоимость часа дважды. См. [§9](#9-правило-двойного-счёта).
Программа предупреждает об этом на `/rates` как о *некапитализированном оборудовании*.

**Покупка лицензии.** Указывайте **9420.3**, а не 9420, по той же причине — регистр
лицензий уже её начисляет.

### Проводка

```
Дт <счёт строки>  (2010 при указанном проекте, иначе 9420)   без НДС, по строке
Дт 4410  НДС к зачёту                                         сумма НДС
    Кт 6010  Кредиторка                                        итого с НДС
```

Содержание: `Xarid hisob-fakturasi <номер>`. Формат номера: **SP-2026-00088**.

### Проверка

- **Кредиторская задолженность** поставщика на `/counterparties` растёт.
- Счёт появляется в `/reports/vat` в разделе НДС к зачёту.
- Если указан проект, растёт себестоимость проекта на `/projects/<id>`.

### С какого банковского счёта уходят деньги

**Где:** боковое меню → Администрирование → **Банковские счета** (`/bank-accounts`)

За одним кодом учёта — 5110 для сумов, 5210 для валюты — обычно стоит несколько реальных
20-значных счетов в банке. Приложение следует логике 1С: счёт учёта остаётся одним кодом,
а каждая проводка по нему указывает банковский счёт как *аналитику* (субконто «Банковские
счета»). Всё, что суммирует деньги по счёту, не меняется; банковский счёт — разбивка под
ним.

Зарегистрируйте каждый счёт один раз на `/bank-accounts`: **Счёт учёта** (5110 или 5210),
**Название**, **Номер счёта**, **Банк**, **МФО**, **Валюта**, и отметьте **По умолчанию**
тот, с которого уходит большинство платежей. Страница затем показывает остаток по каждому
счёту и, для каждого счёта учёта, строку **Без банковского счёта** — проводки, сделанные до
появления справочника.

С этого момента в каждом документе Списание, Поступление, выплате зарплаты и займе есть
выпадающий список **Банковский счёт**, заранее установленный на счёт по умолчанию и
скрытый для платежей из кассы. Это часть платёжного поручения: страница документа
показывает номер счёта плательщика, банк и МФО. Правило, которое приложение соблюдает:

- Счёт учёта, у которого **нет** зарегистрированных банковских счетов, проводится ровно как
  раньше.
- Как только появился хотя бы один, проводка по нему **без** банковского счёта отклоняется
  (*Выберите банковский счёт — счёт 5110 разделён на банковские счета*); так же отклоняются
  счёт в другой валюте, неактивный счёт и счёт другого счёта учёта.
- Выпадающий список определяет счёт учёта: выбор валютного банковского счёта направляет
  деньги на 5210 независимо от способа оплаты.

**Заполнение истории.** Проводки, сделанные до заполнения справочника, не несут банковского
счёта. Если все они относятся к одному реальному счёту — обычный случай — администратор
нажимает **Присвоить** в строке «Без банковского счёта» и выбирает счёт. Меняется только
колонка аналитики: ни сумма, ни дата, ни проводка не затрагиваются, и остаток по счёту
учёта остаётся тем же до тийина. Действие записывается в журнал аудита, повторный запуск
ничего не делает.

**Как это читать.** Карточка счёта 5110 (`/accounts/<id>/card`) показывает остаток по
каждому банковскому счёту и фильтруется до одного — выписка по одному расчётному счёту.
Плитка денег на Панели перечисляет банковские счета под кодами учёта.

> Платёж **без получателя и без распределения** попадает на 9430, который входит в пул
> накладных, — то есть тихо становится накладным расходом и поднимает себестоимость часа
> у всех. Для настоящего неопознанного расхода это может быть ровно тем, что нужно.
> Убедитесь, что это осознанно.

### Платежи, которые не являются расчётами с поставщиками

Используйте табличную часть с явным счётом:

| Что платим | Счёт |
|---|---|
| Зарплату к выплате | 6710 |
| НДФЛ в бюджет | 6420.1 |
| Социальный налог | 6520 |
| Объявленные дивиденды | 6610 |
| Основной долг по займу | 6820 / 7820 |
| Проценты по займу | 9610 |

Для зарплаты и займов программа формирует эти строки сама — см. [§16](#16-зарплата) и
[§17](#17-займы). Вручную вводите только разовые случаи.

## 16. Зарплата

**Где:** боковая панель → Документы → **Зарплата** (`/payroll`)

Зарплата — это ежемесячный цикл из трёх шагов: **сформировать ведомость → начислить →
выплатить**. Начисление фиксирует обязательство, выплата — уход денег.

### Шаг 1 — Сформировать ведомость

Выберите месяц вверху и нажмите **Фильтр**. Программа предложит по строке на каждого
сотрудника, работавшего в этом месяце, взяв зарплату, действовавшую на **последний день**
месяца:

| Колонка | Как считается |
|---|---|
| **Начислено (gross)** | Оклад + премия, из `/staff` |
| **НДФЛ** | Начислено × `tax_rate` (по умолчанию 12%) |
| **Социальный налог** | Начислено × `social_rate` (по умолчанию 12%) |
| **К выплате** | Начислено − НДФЛ (считается, не редактируется) |

Все числа редактируются. Приём в середине месяца, отпуск за свой счёт, разовая премия —
поправьте строку напрямую. Программа предлагает, а не настаивает.

Пять плиток сверху: начислено, НДФЛ, социальный налог, к выплате и полная стоимость для
работодателя (начислено + соцналог).

### Шаг 2 — Начислить

Две кнопки:

- **Сохранить** — сохраняет ведомость черновиком. Ничего не проводится. Пригодится, если
  вы ещё ждёте данные.
- **Начислить** — сохраняет *и* проводит.

Начисление даёт проводку:

```
Дт 2010    Основное производство   начислено + соцналог   по каждому производственному
Дт 9420.2  Административный персонал начислено + соцналог по каждому административному
    Кт 6710   Расчёты по оплате труда  начислено           по каждому сотруднику
Дт 6710    Расчёты по оплате труда  всего НДФЛ
    Кт 6420.1 НДФЛ                     всего НДФЛ
    Кт 6520   Социальный налог          всего соцналог
```

Содержание: `Ish haqi <период>`. Формат номера: **ZP-2026-00009**.

Обратите внимание на две вещи. Зарплата производственных сотрудников идёт на **2010** и
становится затратами проекта. Зарплата АУП идёт на **9420.2** и никогда на 9420 — потому
что административная зарплата уже входит в каждую производственную ставку через долю АУП
([§9](#9-правило-двойного-счёта)).

После начисления **на 6710 остаётся ровно сумма к выплате**.

### Шаг 3 — Выплатить

Карточка выплаты показывает три суммы, которые теперь причитаются. Укажите **Дату** и
**Способ оплаты**, затем нажмите **Списание денег**.

Программа создаёт и проводит одно списание, закрывающее все три:

```
Дт 6710    к выплате
Дт 6420.1  НДФЛ
Дт 6520    соцналог
    Кт 5110 / 5010   итого
```

### Проверка

Карточка **Кредиторская задолженность** показывает сальдо 6710, 6420.1 и 6520. **После
полностью рассчитанного месяца все три должны быть нулевыми.** Это и есть проверка того,
что зарплата и начислена, и выплачена правильно. Ненулевое сальдо означает, что что-то ещё
не выплачено — или проведено дважды.

Карточка истории показывает все месяцы зарплаты, их статус и сумму начисления.

## 17. Займы

**Где:** боковая панель → Документы → **Займы** (`/loans`)

Два вида, и программа везде называет их узбекскими словами:

- **olgan** — деньги, которые бюро **взяло** (обязательство)
- **bergan** — деньги, которые бюро **выдало** (актив)

### Регистрация займа

**[Создать]**:

| Поле | Примечание |
|---|---|
| **Вид** | `olgan` (взятый) или `bergan` (выданный) |
| **Контрагент** | Заимодавец или заёмщик |
| **Сумма**, **Валюта** | Основной долг |
| **Проценты %** | Годовая ставка, справочно |
| **Срок** | `short` → 6820 (или 5820 при выдаче); `long` → 7820 |
| **Дата выдачи** | Обязательно |
| **Срок возврата** | Крайний срок |
| **Способ оплаты** | Через какой денежный счёт проходят деньги |
| **Статус** | `ochiq` (открыт) или `yopilgan` (закрыт) |
| **Провести** | Включите, чтобы сразу отразить движение денег |

Галочка **Провести** здесь намеренно необязательна. Заём, о котором договорились сегодня,
может быть выдан только на следующей неделе; оставьте её снятой, чтобы зафиксировать
договорённость, и проведите деньги отдельно, когда они действительно поступят.

Проводка:

```
olgan  (взяли):    Дт 5110/5010   |  Кт 6820 (кратк.) или 7820 (долгоср.)
bergan (выдали):   Дт 5820        |  Кт 5110/5010
```

### Погашение

Нажмите кнопку суммы в строке займа. Диалог запросит:

- **Дату** и **Способ оплаты**
- **Сумму (основной долг)** — уменьшает остаток по займу
- **Сумму (проценты)** — расход, либо доход, если заимодавец вы

Разделять их обязательно, потому что они идут в разные места:

| | Основной долг | Проценты |
|---|---|---|
| Заём взятый (`olgan`) | Дт 6820 / 7820 | Дт **9610** проценты уплаченные |
| Заём выданный (`bergan`) | Кт 5820 | Кт **9530** проценты полученные |

Погашение взятого займа создаёт списание денег; полученное погашение по выданному займу
создаёт поступление.

### Остаток

Колонка остатка читается напрямую из учёта — 6820/7820 для взятых, 5820 для выданных —
только по документам *этого* займа, и нигде не хранится. Разойтись со счетами она не
может, потому что она *и есть* счета. Два займа одного контрагента ведут раздельные
остатки.

### Как устроена страница

Взятые (`olgan`) и выданные (`bergan`) займы лежат в двух отдельных таблицах. Плитки над
ними показывают по каждой стороне непогашенный итог, сколько займов открыто и закрыто,
остатки не в сумах и сколько займов **просрочено** (срок прошёл, остаток есть).

В каждой строке отдельно **Погашено тела** и **Уплачено %**, а ссылка **История платежей**
раскрывает все документы по займу — выдачу и каждый платёж с разбивкой на тело и
проценты, способом оплаты и статусом. Займ, деньги по которому ещё не проведены,
помечен *не проведён*.

### Автозакрытие

Займ **закрывается сам**, как только остаток основного долга становится нулём, и снова
открывается, если платёж потом аннулируют. Проценты в закрытии не участвуют. Поле
«Статус» в диалоге остаётся для ручного переопределения (например, списанный займ).

## 18. Дивиденды

**Где:** `/documents/dividend` — введите адрес вручную, в меню этой страницы нет.

Дивиденды — это два отдельных события, обычно на разные даты.

**1. Объявление** — решение о выплате:

```
Дт 8710  Нераспределённая прибыль   |   Кт 6610  Расчёты по дивидендам
```

Вводится документом дивидендов. Формат номера: **DV-2026-00002**. С этого момента
учредитель является кредитором бюро.

**2. Выплата** — уход денег. Вводится обычным **Списанием денег**
([§15](#15-списание-денег)) с одной строкой на счёт **6610** и учредителем в получателях:

```
Дт 6610   |   Кт 5110 / 5010
```

После обоих 6610 обнуляется. Ненулевое сальдо на 6610 означает, что дивиденды объявлены,
но ещё не выплачены, — что может быть совершенно правильно.

## 19. Ручные проводки и начальные остатки

### Ручная проводка

**Где:** `/journal` → **[+ Ручная проводка]** (`/documents/manual`)

Для всего, у чего нет своего документа: исправление, начисление, переклассификация.

Заполните дату и описание, затем таблицу: **Счёт**, **Описание**, **Дебет**, **Кредит** —

### Начальные остатки

**Где:** `/documents/opening` — введите адрес вручную. Используется один раз, на старте.

Если у бюро есть история до перехода на v5, вы вводите, где стоял каждый счёт на первый
день. Каждая строка — счёт и его сальдо на правильной стороне.

вводить все счета сразу и не обязательно, чтобы каждый ввод сходился: программа закрывает

```
Дт 5110   Расчётный счёт          45 000 000
Дт 4010   Дебиторка              120 000 000
    Кт 6010  Кредиторка               30 000 000
    Кт 8710  Нераспределённая прибыль 135 000 000
    (0000 принимает разницу)
```

**Когда весь набор введён и учёт действительно сходится, 0000 обнуляется.** Это и есть
проверка. Откройте его карточку (`/accounts` → клик по 0000) — ненулевое сальдо означает,
что чего-то не хватает или что-то введено неверно.

Формат номера: **OB-2026-00001**.

## 20. Табель

**Где:** боковая панель → Сотрудники → **Табель** (`/staff/hours`)

Отработанные часы по людям, проектам и месяцам. Это связь между себестоимостью часа и
проектами, которые бюро реально сделало.

### Ввод часов

**[Создать]**:

| Поле | Примечание |
|---|---|
| **Проект** | Обязательно |
| **Сотрудник** | Обязательно |
| **Период** | `ГГГГ-ММ`, например `2026-03`. Формат проверяется. |
| **Часов** | Шаг 0,5 |

На каждого человека, проект и месяц приходится одна строка. Повторный ввод той же
комбинации **заменяет** существующее значение, а не прибавляется к нему, — вводите итог за
месяц, а не каждый день.

Селектор периода вверху фильтрует список и отправляется автоматически.

### Импорт табеля NIZAM

**[⇧ Импорт NIZAM]** вверху страницы принимает месячную выгрузку `table.xlsx` из CRM NIZAM
и записывает часы за месяц одним действием.

| Поле | Примечание |
|---|---|
| **Файл** | Выгрузка NIZAM. Во 2-й строке — имена сотрудников начиная с колонки D; каждая строка данных — проект с часами по людям в формате `ЧЧ:ММ`. |
| **Период** | `ГГГГ-ММ`, который покрывает лист. Все часы файла ложатся в этот месяц. |
| **Создавать неизвестные проекты** | Включено: проект, которого нет в реестре, создаётся. Выключено: он попадает в отчёт и очередь на сопоставление. |

Правила, все — намеренные:

- **Сотрудники сопоставляются, но никогда не создаются.** Заголовок колонки ищется по
  `nizam_name` в реестре, затем по имени или полному имени (без учёта регистра), затем
  по старой карте NIZAM. Несопоставленное имя попадает в предупреждение; добавьте или
  переименуйте сотрудника на странице «Сотрудники» и повторите импорт. Совпадение
  записывает `nizam_name` обратно, чтобы следующий импорт был точным.
- **Небиллинговые строки** (Office, HR, внутренние задачи…) и строки без часов
  пропускаются, и в подтверждении перечислены все пропуски с причиной.
- **Повторный импорт того же месяца обновляет часы на месте.** Привязка к этапу и
  снимок ставки на строке сохраняются.
- Существующие проекты находятся по псевдонимам и нормализованному названию, поэтому
  переименованный в NIZAM проект не раздваивается.

### Зачем нужны часы

Часы питают четыре вещи:

1. **Себестоимость проекта** — часы × себестоимость часа этого человека.
2. **Загрузку** — оплачиваемые часы против доступных, по каждому, на `/rates`.
3. **Базу распределения** — если бюро использует базу по часам, а не по оплате труда,
   именно эти часы определяют, кто какую долю накладных принимает.
4. **Готовность проекта и заработанную выручку** — фактические часы против плановых.

### Колонки применённых ставок

В списке рядом с часами показаны **Применённая себестоимость часа** и **Итого**. Для
открытого месяца они пусты и заполняются при закрытии периода или фиксации ставок: ставка,
действовавшая на тот момент, проставляется в строку и больше не пересчитывается. Именно это
не даёт закрытой истории меняться при последующем изменении зарплат.

### Поле, которое важнее всех

**Тип** сотрудника определяет, как обходятся с его стоимостью, и меняет все цифры дальше:

Панель фильтров сужает реестр по **отделу**, **типу** (производство / администрация),

### Добавление сотрудника

**[Создать]**:

| Поле | Примечание |
|---|---|

| **ФИО** | Полное имя. |
| **Роль** | Обязательно. Список ранее использованных ролей. |
| **Отдел** | Обязательно. Аналогично. |
| **Тип** | Производственный или административный — см. выше. |

**Табельный номер** присваивается автоматически: `MZ-###` для производственных, `MA-###`

### История зарплат

Зарплата — это временная шкала, а не одно поле. **[+ Оклад]**:

| Поле | Примечание |
|---|---|
| **Сотрудник** | Обязательно |
| **Действует с** | Обязательно. Дата начала новой зарплаты. |
| **Оклад** | Месячный оклад |
| **Премия** | Регулярная месячная премия сверху |

Добавление зарплаты **автоматически закрывает предыдущую** днём раньше новой даты начала.
Старую строку вы никогда не правите — вы добавляете новую, а программа поддерживает шкалу.

Именно из-за этой шкалы зарплатная ведомость за март использует мартовскую зарплату, даже
если вы формируете её в августе, и именно поэтому закрытие периода фиксирует правильные
ставки.

В списке показаны **Себестоимость часа** и **Ставка продажи** каждого производственного
сотрудника. У сотрудника без записи о зарплате показывается *Зарплата не задана* и ссылка
на исправление — а не ноль. Ноль тихо занижал бы каждый проект, которого этот человек
касался.

### KPI сотрудников

**Где:** боковое меню → Сотрудники → **KPI** (`/kpi`)

По строке на каждого производственного сотрудника, по убыванию часов: на сколько
проектов он списывал время, его биллинговые часы за всё время, себестоимость и ставка

Различие, которое важно держать в голове:

- **Тип** (`kind`) отвечает на вопрос **кто несёт затраты**. `personal` относится на
  ставку одного названного сотрудника. `general` распределяется на всех производственных.
- **Класс актива** отвечает на вопрос **что это за вещь**. Он задаёт срок службы и пару
  счетов учёта, на которых идёт амортизация.

Они независимы. Стол и ноутбук могут быть оба `personal`, но это разные классы. Общий
плоттер и общий переговорный стол оба `general` — и снова разные классы.

### Классы активов

| Класс | Счёт актива | Накопленная амортизация | Срок по умолчанию |
|---|---|---|---|
| Компьютерное оборудование | 0150 | 0250 | 36 мес. |
| Мебель и офисное оборудование | 0140 | 0240 | 36 мес. |
| Машины и оборудование | 0130 | 0230 | 36 мес. |
| Транспортные средства | 0160 | 0260 | 36 мес. |
| Здания и сооружения | 0120.1 | 0220.1 | 36 мес. |
| Прочие основные средства | 0190 | 0290 | 36 мес. |

Все классы поставляются с 36 месяцами. Это то единственное значение, с которым был заведён
весь регистр в v4, поэтому введение классов не сдвинуло ни одной цифры при переходе.
Установить реальные сроки — решение бюро.

Для справки: Налоговый кодекс (ст. 306 §30) ограничивает амортизацию 20% в год для
компьютеров (60 месяцев) и 15% в год для мебели (80 месяцев). 36 месяцев — это 33,3% в
год, выше обоих потолков. Но это *налоговые* ограничения; по НСБУ №5 бухгалтерский срок —
собственная оценка бюро, поэтому здесь это настройка.

**Изменение срока по классу — работа администратора**, в карточке классов активов:
исправьте поле **Срок по умолчанию (мес.)** и нажмите **Сохранить**.

> **Срок по умолчанию — только по умолчанию.** Его изменение влияет на активы, введённые
> *после*. Оно никогда не переопределяет срок уже записанного актива — иначе сдвинулась бы
> уже проведённая амортизация и все посчитанные по ней ставки. Строки, срок которых
> отличается от классового, помечены значком **Отличается**, чтобы расхождение было видно.

### Переклассификация

Кнопка **Переклассифицировать** угадывает класс каждого актива по его наименованию,
используя правила по ключевым словам, и делает это аккуратно в двух отношениях: она трогает
только строки, оставшиеся в классе *Прочие*, поэтому сделанное вручную исправление никогда
не затирается; и она показывает, что именно собирается сделать.

Названия машин распознаются раньше названий аксессуаров, потому что в карточке ноутбука
регулярно перечислен и его монитор.

### Лицензии

Revit, 3ds Max, AutoCAD — всё, за что платится годовая плата.

| Поле | Примечание |
|---|---|
| **Наименование** | Обязательно |
| **Сотрудник** | Кому назначена |
| **Годовая стоимость** | Месячная = эта сумма ÷ 12 |
| **Активная** | Снимите по истечении |

### Бюджет накладных расходов

**Запасной** источник накладных, используемый только когда учёт не может их дать. Простые
строки: аренда офиса, коммунальные, интернет, питание, транспорт, прочее.

> Эта таблица поставляется **заполненной демонстрационными цифрами** (аренда офиса
> 25 000 000 и т. д.). Если ваши ставки строятся по этой таблице, а не по учёту, они
> строятся по примерным числам. `/rates` предупреждает об этом. См.

Кнопка **[Бухгалтерия]** открывает страницу сверки двух источников.

## 23. Себестоимость часа

**Где:** боковая панель → Сотрудники → **Себестоимость часа** (`/rates`)

Главный результат всей программы.

### Плитки

| Плитка | Что означает | Норма |
|---|---|---|
| **Ставка накладных** | Косвенные затраты в процентах от прямой оплаты труда | 150–180% |
| **Загрузка** | Оплачиваемые часы ÷ доступные часы | 75–85% |
| **Доступные часы** | Рабочих часов на человека в месяц | ~151 |
| **Средняя себестоимость часа** | Со ставкой продажи под ней | — |
| **Полная месячная себестоимость** | Полная месячная стоимость посчитанного персонала | — |

Три эталонных диапазона взяты из международной проектной практики (AIA/PSMJ,
FAR Part 31 / AASHTO). Они **только показываются** — программа никогда не подставляет их
обратно в расчёт. Они говорят, выглядит ли бюро нормально, а не сколько брать с заказчика.

### Как читать таблицу

| Колонка | Что это |
|---|---|
| **Табельный №** | `MZ-###` |
| **Начислено (gross)** | Оклад + премия |
| **Налог + соцналог** | Нагрузка работодателя на начисленное |
| **Доля АУП** | Его доля во всех административных зарплатах |
| **Доля накладных** | Его доля в косвенном пуле |
| **Доля оборудования** | Личное оборудование + лицензии + доля общего оборудования |
| **Полная месячная себестоимость** | Сумма всего вышеперечисленного |
| **Оплачиваемые часы** | Из табеля |
| **Загрузка** | Оплачиваемые ÷ доступные, с цветовой шкалой |
| **Ставка накладных** | Его косвенные затраты в % от его прямой оплаты труда |
| **Себестоимость часа** | **Та самая цифра.** Полная месячная себестоимость ÷ доступные часы |
| **Ставка продажи** | Себестоимость часа × наценка |
| **Net multiplier** | Ставка продажи ÷ «голая» ставка оплаты труда |

Кнопка **Печать** даёт чистую версию для совещания.

Столбец **Ставка биллинга $** — ставка биллинга по текущему курсу доллара, под ней —
себестоимость в долларах: цифра, которую называют иностранному клиенту.

### Два переключателя

Карточка **База расчёта** содержит настройки, меняющие *способ* построения ставки. Оба —
**уровня администратора**.

**База распределения** — как делятся общие расходы:

| Вариант | Смысл | Когда использовать |
|---|---|---|
| **По оплате труда** (по умолчанию) | Доля пропорциональна стоимости зарплаты | Стандартная база. Час ведущего специалиста действительно принимает больше накладных, чем час младшего. |
| **По часам** | Доля пропорциональна оплачиваемым часам | Поведение v4. Выберите, чтобы в точности воспроизвести цифры v4. |

**Источник накладных** — откуда берётся сумма накладных:

| Вариант | Смысл | Когда использовать |
|---|---|---|
| **Бухгалтерия (факт)** (по умолчанию) | Скользящее среднее фактически проведённых косвенных расходов | Когда накопилось несколько месяцев реальных проводок |
| **Таблица (план)** | Таблица, заполняемая вручную на `/staff/equipment` | Только пока в учёте нет истории |

Там же: **Наценка** (2,0), **праздники** в году (14), средний **отпуск** в днях (20) и
**окно накладных** в месяцах (12).

### Кнопка фиксации периода

**[Сохранить период]** фиксирует ставки выбранного месяца в постоянном хранилище.
Нажимайте её перед закрытием месяца — хотя закрытие сделает это и само.

Важная деталь: фиксация считает период **по состоянию на последний день этого периода**, а
не на сегодня. Фиксация марта в августе использует мартовские зарплаты, мартовское окно
накладных и активы, живые в марте.

### Два предупреждения

**Переход на запасной источник накладных:**

> *Ставки считаются по табличному значению*

Программа хотела взять учёт и не смогла. Причина показана рядом — см.
[§24](#24-сверка-накладных-расходов). Ваши ставки сейчас строятся по таблице, которая
поставляется с демонстрационными числами. Это стоит считать срочным.

**Некапитализированное оборудование:**

> *Некапитализированное оборудование (нет на 0150)* — *Эти активы списаны на 9420, поэтому
> регистр начисляет их в ставки повторно*

Оборудование было куплено по счёту-фактуре и списано на 9420 вместо капитализации на счёт
актива, при том что регистр оборудования его тоже амортизирует. Стоимость попадает в
ставки дважды. Исправление — в [§14](#14-счёт-фактура-полученный).

## 24. Сверка накладных расходов

**Где:** `/rates/overhead` — кнопка **[Бухгалтерия]** на странице оборудования или ссылка
на `/rates`

Одна задача: показать, какова сумма накладных, откуда она взялась и — если не оттуда,
откуда вы просили, — почему.

### Три плитки

- **Бухгалтерия (факт)** — месячное среднее по учёту, с использованным окном и реальным
  количеством месяцев истории
- **Таблица (план)** — итог статической таблицы
- **Отклонение** — разница

Активный источник подсвечен. Ниже — разбивка пула по счетам, чтобы было видно, какие счета
в него вносят вклад.

### Как строится сумма по учёту

Все счета с признаком **Косвенные** (по умолчанию 9410, 9420, 9430) суммируются за
скользящее окно — дебет за вычетом кредита — и делятся на реально прошедшие месяцы. Вычет
кредита нужен для того, чтобы возврат корректно уменьшал накладные.

### Коды причин

| Причина | Значение | Что делать |
|---|---|---|
| `ledger` | Работает нормально | Ничего |
| `disabled` | Вы сами выбрали таблицу | Ничего, если это осознанно |
| `ledger_empty` | *В учёте нет проводок накладных расходов* | Нормально на новой установке. Проведите реальные расходы. |
| `ledger_stale` | *Все проводки старше окна — расширьте окно* | Увеличьте окно накладных на `/rates`. |
| `pool_negative` | *Пул отрицательный: доход мог попасть на 9430* | Найдите — см. ниже. |

### Отрицательный пул

Отрицательный пул накладных не бывает верным ответом, поэтому программа его отвергает и
переходит на запасной источник. Причина почти всегда — доход, попавший на **9430**, обычно
поступление, введённое без контрагента, которое программе пришлось куда-то отнести
([§7](#7-погашение--это-распределение-а-не-галочка)).

Как найти: откройте карточку счёта 9430 (`/accounts` → клик по 9430) и посмотрите на записи
по кредиту. Сторнируйте виновный документ и введите заново с заполненным контрагентом.

## 25. Проекты и лестница цен

**Где:** боковая панель → Проекты → **Проекты** (`/projects`), затем клик по названию

### Создание проекта

**[Создать]**: Наименование (обязательно), Код, Заказчик, Ответственный, Сумма договора,
Валюта, Даты начала и окончания, Плановые часы, Статус (`активный` / `завершён` /
`приостановлен`), Примечания и галочка **Оплачиваемый**. Снимите её для внутренних работ.

### Список проектов

В каждой строке — **часы** за всё время, число **людей**, которые их списали, этапы
выполнено / всего с красным счётчиком **просроченных**, и статус плана. По умолчанию
список отсортирован по часам; селектор **Сортировка** предлагает название, статус, договор
и дату начала.

### Карточка проекта

Восемь плиток: **Сумма договора**, **Выставлено**, **Себестоимость** (с часами),
**Прибыль** (с маржой), **Готовность** (с заработанной выручкой), **Освоенный объём**
(сумма планового дохода каждого этапа × его готовность), **Курсовая разница** по
валютным счетам проекта и **В графике** — светофор, описанный ниже в разделе
«Помесячно план / факт».

Ниже — карточка планирования и ценообразования, где проект и планируется, и оценивается.

### Факторы риска

Четыре взвешенных фактора, сохраняемые на проекте:

| Фактор | Низкий = 1 | Средний = 2 | Высокий = 3 | Вес |
|---|---|---|---|---|
| **Срок** | больше 8 месяцев | 4–8 месяцев | меньше 4 месяцев | 30% |
| **Тип заказчика** | Постоянный | Новый | Государственный | 25% |
| **Сложность** | Простой | Средний | Высокий | 25% |
| **Валюта** | UZS | USD | Другая | 20% |

Из них получается коэффициент риска:

```
коэффициент риска = 1 + (взвешенный балл - 1) x 0,15
```

**Риск повышает цену. Себестоимости он не касается никогда.** Плановая себестоимость не
включает риск, поэтому план и факт сравниваются на одной базе.

### Этапы и есть план

График этапов *и есть* план проекта. Отдельного экрана планирования нет.

**[+ Этап]** или **[+ Этапы (6)]** — вторая кнопка создаёт шесть стандартных стадий
проектирования пустым каркасом, только названия и виды работ.

Каждый этап содержит:

| Поле | Примечание |
|---|---|
| **Наименование** | Обязательно |
| **Код**, **Порядок** | Короткий код (уникальный внутри проекта) и позиция в таблице |
| **Вид работ**, **Начало**, **Окончание** | График |
| **Таблица сотрудников** | Кто работает и сколько часов. Диалог показывает актуальную себестоимость часа каждого. |
| **План аутсорсинга**, **План материалов** | Прямые расходы |
| **План дохода** | Цена. Предлагается автоматически, можно переопределить. |
| **Готовность %**, **Статус** | `запланирован` / `в работе` / `выполнен` / `отменён` |

Плановые часы и плановая себестоимость выводятся из таблицы сотрудников: часы ×
себестоимость часа этого человека.

### Лестница цен

Применяется одинаково к одному этапу и к проекту целиком:

```
минимальная = себестоимость труда x коэффициент риска + аутсорсинг + материалы
целевая     = минимальная / (1 - целевая маржа)      <- целевая маржа 50% по умолчанию
премиум     = целевая x 1,2
```

- **Минимальная цена** — ниже неё проект убыточен
- **Целевая цена** — цена, реально дающая целевую маржу
- **Премиум цена** — запрос, когда есть запас

Лестница линейна по своим входам, а значит сумма целевых цен по этапам всегда в точности
равна целевой цене от суммы затрат. Цифры этапов и итоги проекта не могут разойтись.

**[Применить рекомендованные цены]** записывает предложенную целевую цену в план дохода
каждого этапа — но не трогает цены, которые вы правили вручную, если не потребовать этого
явно. Отредактированная цена помечается. Ноль означает «ещё не оценено», а не
переопределение. Отменённые этапы исключаются и из цены, и из свода.

### Фиксация плана

**[Зафиксировать план]** копирует текущий живой план на проект как постоянную базу, с
отметкой даты. Именно с этой базой страница «Бюджет» сравнивает факт.

Два уровня существуют намеренно:

- **Живой план** на этапах пересчитывается при каждой правке.
- **Зафиксированная база** на проекте меняется только по нажатию кнопки.

Без такого разделения планка сдвигалась бы при каждой корректировке оценки, и на вопрос
«вышли ли мы за бюджет?» нельзя было бы ответить.

Фиксация отклоняется на проекте без этапов, поэтому база не может быть случайно обнулена.
Когда живой план уходит от зафиксированной базы, появляется значок **План изменился —
зафиксируйте заново**.

### Помесячно план / факт

Под карточкой планирования таблица **Помесячно план / факт** распределяет план каждого
датированного этапа по месяцам, которые он покрывает (пропорционально дням), и ставит
рядом с ним факт месяца: выручку, проведённую на 9030, прямые расходы на 2010 и часы
табеля по себестоимости. В каждой строке — план и факт дохода, расходов и прибыли,
отклонение за месяц и обе прибыли нарастающим итогом. Текущий месяц выделен и никогда
не оценивается — доход приходит в конце месяца, — а месяц с фактом без плана помечен
*вне плана*.

Над таблицей три показателя «на дату» по месяцам строго до текущего: **отклонение
прибыли** (факт минус план, в % от планового дохода), **поступления** (факт дохода к
плану) и **отклонение расходов**.

Они и определяют светофор **В графике** на плитке:

| Свет | Зелёный | Жёлтый | Красный |
|---|---|---|---|
| **Прибыль** | отклонение ≥ −5 % | −15 … −5 % | ниже −15 % |
| **Сроки** | нет просроченных этапов | этап отстаёт от ожидаемой готовности более чем на 15 пунктов | этап с прошедшим сроком и не выполнен |
| **Поступления** | ≥ 95 % планового дохода получено | 85–95 % | меньше 85 % |

Общий вердикт красный, если красен любой свет, жёлтый — если любой жёлтый, серый — когда
нет датированного плана. Этапы с планом, но без дат перечислены в предупреждении: их
нельзя разложить по месяцам.

### Факт без привязки к этапу

Часы и проведённые счета, у которых есть проект, но нет этапа, перечислены под
помесячной таблицей. Для каждого месяца табеля заранее подставлен этап, который его
больше всего перекрывает; **Привязать** прикрепляет весь месяц. Проведённый счёт
привязывается так же — меняется только измерение «этап» на документе и его проводках,
но никогда сумма, дата или счёт. Факт по этапам (и показатели CPI / SPI) видит деньги и
часы после привязки; помесячной таблице привязка вообще не нужна.

### Быстрое КП для потенциального клиента

**Где:** боковое меню → Проекты → **Ценообразование** (`/pricing`)

Клиента без карточки проекта тоже можно оценить. Заполните таблицу графика — название
этапа, вид работ, месяцы, часы по людям, аутсорсинг и материалы, — задайте четыре фактора
риска и нажмите **Рассчитать**: каждая строка проходит ту же лестницу цен, что и карточка
проекта, а над таблицей появляются три цены договора. Таблица пересчитывается по мере
ввода. **Стандартный график (6)** заполняет шесть стадий проектирования.

Ничего не сохраняется, пока вы не выберете проект в селекторе и не нажмёте **Сохранить в
проект**: строки становятся этапами этого проекта вместе с часами сотрудников, а факторы
риска записываются в него. Проект, у которого уже есть этапы, отклоняется, если не
отмечено «Заменить существующие этапы», и всегда — если к этапам привязаны документы.
Таблица проектов ниже — вход в полное рабочее место «План и цена» для существующих
проектов.

## 26. Бюджет

**Где:** боковая панель → Проекты → **Бюджет** (`/budget`)

Зафиксированный план каждого проекта против его живого факта, на одной странице.

Четыре плитки: **План всего**, **Факт всего**, **Отклонение** (в сумме и в процентах) и
количество проектов **без плана**.

По каждому проекту: плановые и фактические часы, плановая и фактическая себестоимость,
итоги плана и факта, отклонение, выручка и прибыль. Значки статуса:

| Значок | Значение |
|---|---|
| **Превышение бюджета** | Больше чем на 5% выше плана |
| **В пределах бюджета** | Больше чем на 10% ниже плана |
| **На границе** | Между ними |
| **Нет плана** | Никогда не фиксировался |

**Проект без зафиксированного плана исключается из плановых итогов**, а не получает план,
выдуманный из его же факта. Это сохраняет честность портфельного отклонения: сравнение
факта с самим собой всегда показывало бы идеальное исполнение.

ФАКТ пересчитывается живьём из фактических часов по текущим ставкам. ПЛАН — зафиксированная
цифра, и она не двигается.

### Вторая линза: на дату

Первая таблица отвечает на вопрос *уложимся ли мы в бюджет?* Вторая, **На дату — план /
факт**, — *там ли мы, где должны быть сейчас?* По каждому проекту она показывает
помесячный план этапов против факта за месяцы до текущего, отклонение прибыли и долю
поступлений, светофор с тремя огнями и месяцы, которые покрывает план. Ещё две плитки
сверху считают проекты в графике / на грани / вне графика и сводят прибыль на дату с
планом.

Две линзы измеряют разное и никогда не сводятся в одну цифру. Проект может укладываться
в бюджет в целом и при этом отставать в этом месяце.

# Часть V — Закрытие месяца и отчёты

## 27. Чек-лист закрытия месяца

Проходите его раз в месяц по порядку. Порядок не произволен: несколько шагов зависят от
предыдущих, а один из них (амортизация) даёт неверный результат, если выполнить его после
закрытия.

Шаги закрытия — **уровня администратора**.

---

**☐ 1. Провести все документы месяца**

Черновиков остаться не должно. На панели показано их количество; каждый список документов
фильтруется по **Статус → Черновик**.

После закрытия периода документ с датой внутри него провести уже нельзя.

---

**☐ 2. Внести курс на конец месяца**

`/settings` → карточка **Курс валюты** → дата и курс → **Сохранить**.

Переоценка валюты на шаге 4 берёт последний курс на указанную дату или раньше. Без
свежего курса она переоценит по устаревшему.

Пропустите, если у бюро нет валютных остатков.

---

**☐ 3. Рассчитать зарплату**

`/payroll` → выберите месяц → **Фильтр**.

1. Проверьте каждую строку. Поправьте приём в середине месяца, отпуск за свой счёт,
   разовую премию.
2. **Начислить**.
3. В карточке выплаты укажите дату и способ, затем **Списание денег**.
4. Убедитесь, что в карточке кредиторской задолженности **6710, 6420.1 и 6520 обнулились**.

Эти три нуля — доказательство, что зарплата и начислена, и выплачена. См.
[§16](#16-зарплата).

---

**☐ 4. Провести переоценку валюты**

`/periods` → карточка переоценки → укажите дату → **Переоценка валюты**.

Она пересчитывает все валютные остатки по текущему курсу, относя разницу на 9540 (доход)
или 9620 (убыток). Пропустите, если валютных остатков нет.

---

**☐ 5. Просмотреть предварительный расчёт амортизации**

`/periods` → карточка амортизации → выберите месяц.

Предпросмотр показывает, что именно будет проведено: каждый актив, использованные месяцы,
начисление и остаточную стоимость. **Пока ничего не записывается.**

Посмотрите таблицу **Пропущенные объекты** ниже. У каждого пропуска есть причина:

| Причина | Значение | Что делать |
|---|---|---|
| *Нет даты покупки* | В строке регистра нет даты | **Исправьте.** Добавьте дату на `/staff/equipment` |
| *Некорректная дата покупки* | Дата не читается | Исправьте |
| *Ещё не куплено* | Куплено позже этого месяца | Ничего, это правильно |
| *Полностью самортизировано* | Срок службы исчерпан | Ничего, это правильно |
| *Не задан срок службы* | Пустой срок | Задайте или оставьте пустым для срока по классу |
| *Нулевая стоимость* | Цена равна нулю | Введите цену |

*Нет даты покупки* важнее остальных: движок ставок начисляет такой актив в себестоимость
часа **бесконечно**, а учёт его никогда не амортизирует. Исправьте эти строки — и регистр с
учётом останутся в согласии.

Затем нажмите **Провести амортизацию**.

```
Дт 9420.1  Расходы на амортизацию   (по сотруднику для личных активов, одной строкой для общих)
    Кт 0250 / 0240 / 0230 / ...       (по строке на класс актива)
```

Повторный запуск безвреден — программа увидит, что месяц уже проведён, и ничего не сделает.

---

**☐ 6. Зафиксировать ставки за период**

`/rates` → **[Сохранить период]**.

Ставки месяца фиксируются навсегда, рассчитанные на последний день месяца. Если пропустить,
закрытие сделает это само — но здесь у вас есть возможность сначала посмотреть на цифры.

---

**☐ 7. Проверить, что учёт сходится**

`/trial-balance` — баннер сверху должен сообщать:

> *Баланс сходится: дебет = кредит*

`/reports/balance-sheet` — баннер должен сообщать:

> *Баланс сходится: актив = пассив*

Если хоть один показывает предупреждение, **остановитесь и разберитесь до закрытия**. См.
[§38](#38-когда-два-числа-не-сходятся).

---

**☐ 8. Прочитать результаты месяца**

`/reports/pnl` за месяц и `/reports/cashflow`. Это момент, когда нужно заметить странное:
после закрытия исправления потребуют открытия периода.

---

**☐ 9. Закрыть период**

`/periods` → строка месяца → **Закрыть период** → подтвердить.

Закрытие:

1. Проведёт амортизацию, если шаг 5 был пропущен
2. Прочитает отчёт о прибылях и убытках
3. Зафиксирует ставки месяца и проставит их в строки табеля
4. Запишет проводку закрытия — все счета доходов и расходов закроются на **9910**
5. Заблокирует период

Закрыть можно **мягко** (обратимо по смыслу) или **жёстко** (обычное финальное состояние).
Оба варианта одинаково отклоняют новые проводки.

## 28. Отчёты

Все отчёты доступны только для чтения и открыты любому пользователю.

### Отчёт о прибылях и убытках — `/reports/pnl`

Доходы и расходы за период, по умолчанию с начала года. Счета доходов сгруппированы и
подытожены, счета расходов тоже, затем валовая прибыль, чистая прибыль и целевая маржа.

*Если выглядит неверно:* проверьте, что все документы периода проведены, а не остались
черновиками — черновик не попадает ни в один отчёт.

### Баланс — `/reports/balance-sheet`

Актив с одной стороны, пассив и капитал с другой, на дату. Контрактивные счета
(накопленная амортизация) показаны в скобках как вычет. Баннер подтверждает, что баланс
сходится.

*Если не сходится:* проблема на уровне учёта, а не отчёта. Сначала откройте
`/trial-balance`.

### Движение денег — `/reports/cashflow`

Приход, расход, чистый поток и остаток по периодам, с плиткой по каждому денежному счёту и
плиткой конечного остатка.

*Если выглядит неверно:* конечный остаток должен совпадать с суммой сальдо счетов 5xxx и с
плиткой денежных средств на панели. Если эти три расходятся, см.
[§38](#38-когда-два-числа-не-сходятся).

Под помесячной таблицей блок **По способу оплаты** делит поступления и выплаты того же
периода по способу на документе — банк, наличные, карта, онлайн, — считая по денежным
счетам, поэтому его итоги равны итогам движения денег выше.

### Отчёт по НДС — `/reports/vat`

НДС начисленный (6410.1) против НДС к зачёту (4410) за период, с разницей как НДС к уплате.
Оба раздела перечисляют документы с контрагентом и ИНН.

*Если документа нет:* в его строках нет суммы НДС, либо он ещё черновик.

### Дебиторка / Кредиторка — `/reports/aging`

Переключатель **Дебиторка** / **Кредиторка**. Остатки разложены по срокам: 0–30, 31–60,
61–90, 90+ дней. Всё старше 60 дней помечается как просроченное.

Две таблицы: итоги по контрагентам и сами документы со сроками оплаты и днями просрочки.

*Если счёт, за который вам заплатили, всё ещё здесь:* платёж существует, но не был
**распределён** на этот счёт. Откройте платёж и распределите его ([§13](#13-поступление-денег)).

### Журнал проводок — `/journal`

Все проводки, свежие сверху, сгруппированные по документам. Фильтр по датам, счёту, проекту
и контрагенту. Сторно помечено. Каждый код счёта ведёт в его карточку.

Сюда идут, чтобы ответить на вопрос «что вообще произошло».

### Оборотно-сальдовая ведомость — `/trial-balance`

Сальдо на начало, обороты и сальдо на конец по каждому счёту, каждое с разбивкой на дебет и
кредит. Баннер сообщает, сходится ли учёт. Галочка «все» включает счета с нулевым сальдо.
Есть кнопка **Печать**.

### Карточка счёта — `/accounts/<id>/card`

Все движения по одному счёту с нарастающим остатком, плюс четыре плитки: сальдо на начало,
дебет, кредит, сальдо на конец. Открывается кликом по коду счёта в любом месте программы.

Это инструмент для поиска конкретной неверной цифры.

## 29. Открытие закрытого периода

**Где:** `/periods` → строка закрытого месяца → **Открыть период**. **Только администратор.**

Открытие возвращает период в состояние «открыт» и сторнирует две вещи:

1. **Проводку закрытия** — сальдо доходов и расходов возвращаются на свои счета с 9910
2. **Проводку амортизации** за этот месяц

Амортизация сторнируется намеренно. Если бы её оставили, повторное закрытие пропустило бы
её как уже проведённую, и любое исправление регистра оборудования, сделанное во время
открытия, было бы тихо проигнорировано.

**Жёстко закрытый** период здесь не откроется — только мягко закрытый. Разницу см. в
[§10](#10-периоды).

### После открытия

1. Внесите исправления, ради которых открывали.
2. **Закройте период заново** — пройдите [§27](#27-чек-лист-закрытия-месяца) начиная с
   шага 5.

Открытый и не закрытый заново период оставляет годовые цифры неверными: доходы и расходы
месяца висят на своих счетах вместо финансового результата.

# Часть VI — Администрирование

## 30. Параметры

**Где:** боковая панель → Администрирование → **Параметры** (`/settings`). Сохранение —
**только администратор**.

Каждый параметр — число. Показаны название, единица измерения и внутренний ключ.

| Ключ | По умолчанию | Что делает | Менять? |
|---|---|---|---|
| `usd_rate` | 12850 | Справочный курс доллара | Редко — настоящий источник это таблица курсов |
| `tax_rate` | 0.12 | Ставка НДФЛ (JSHDS) | Только при изменении закона |
| `social_rate` | 0.12 | Ставка социального налога работодателя | Только при изменении закона |
| `vat_rate` | 12 | НДС % по умолчанию в новых строках счетов | **Поставьте 0, если бюро на упрощённом режиме** |
| `billing_multiplier` | 2.0 | Наценка: ставка продажи ÷ себестоимость часа | Решение уровня бюро |
| `target_margin` | 0.5 | Целевая маржа в лестнице цен | Решение уровня бюро |
| `holidays_per_year` | 14 | Праздничные дни, для расчёта доступных часов | При изменении календаря |
| `avg_leave_days` | 20 | Средний отпуск и болезни в году | Когда меняется ваше реальное среднее |
| `utilization_rate` | 0.75 | Целевая загрузка, справочно | Редко |
| `kpi_months` | 43 | Окно KPI / мощности в месяцах | Редко |
| `overhead_from_ledger` | 1 | 1 = учёт, 0 = таблица | Пользуйтесь переключателем на `/rates` |
| `overhead_window_months` | 12 | Скользящее окно усреднения накладных | Расширьте при `ledger_stale` |
| `allocation_base_labor_cost` | 1 | 1 = оплата труда, 0 = часы | Пользуйтесь переключателем на `/rates` |
| `default_vat_on_sales` | 1 | Подставлять НДС в новые строки продаж | Если большинство продаж без НДС |

> **`vat_rate` — то, что стоит проверить на новой установке.** Программа исходит из того,
> что бюро является плательщиком НДС по ставке 12%. Если оно на упрощённом режиме,
> поставьте 0, и НДС в новые строки добавляться не будет. Больше ничего менять не нужно.

Изменение `billing_multiplier`, `holidays_per_year` или `avg_leave_days` немедленно меняет
все часовые ставки в бюро. Закрытые периоды сохраняют свои зафиксированные ставки и не
затрагиваются.

## 32. План счетов и настройка проводок

**Где:** боковая панель → Администрирование → **План счетов** (`/accounts`). Правка —
**только администратор.**

В списке показан каждый счёт с кодом, наименованиями, видом, субконто, группой затрат,

### Правка счёта

| Поле | Примечание |
|---|---|
| **Код счёта** | Задаётся при создании, потом не меняется |

| **Активный** | Снимите, чтобы убрать из списков |

### Поле «Группа затрат»

| Значение | Смысл |
|---|---|
| *(пусто)* | Не участвует в расчёте ставок |
| **Прямой труд** | Производственный труд, накапливающийся на проектах |
| **Косвенные (накладные)** | Попадает в пул накладных и распределяется на производственных сотрудников |
| **Не учитывается** | Реальный расход, уже начисляемый из регистра — не считать его повторно |

> **Не ставьте 9420.1, 9420.2 и 9420.3 в «Косвенные».** Эти расходы уже попадают в
> себестоимость часа через регистры оборудования, сотрудников и лицензий. Признак
> «Косвенные» начислит их дважды и завысит все ставки в бюро. Программа отклонит
> соответствующие проводки и вернёт признак при перезапуске, но до этого ставки на экране
> будут неверными. Полное объяснение — [§9](#9-правило-двойного-счёта).

### Настройка проводок

Вторая карточка, **Проводка → Счёт**, сопоставляет каждое *назначение* проводки с реальным
счётом: «счёт дебиторки», «расчётный счёт», «счёт выручки» и ещё около тридцати.

Ни в одном месте логики программы код счёта не зашит — каждое правило запрашивает
назначение и ищет его здесь. Чтобы все банковские движения шли на другой счёт, поменяйте
это здесь один раз, и все последующие проводки пойдут туда. Уже сделанные проводки не
затрагиваются.

## 34. Курсы валют

**Где:** `/settings` → карточка **Курс валюты**. **Уровень менеджера.**

Укажите **Дату** и **Курс** (сумов за 1 доллар) и нажмите «Сохранить». Ввод существующей
даты обновляет её. В карточке показан текущий курс и история последних 40 значений.

**[Курс ЦБ]** рядом с полем даты запрашивает у Центрального банка Узбекистана
официальный курс доллара на эту дату и подставляет его в поле; **Сохранить** всё равно
нажимаете вы. Если `cbu.uz` недоступен, поле остаётся пустым и подпись сообщает об этом —
введите курс вручную. История курсов под формой полная, новые сверху.

### Как выбирается курс

Когда программе нужен курс на дату, она берёт **последний курс на эту дату или раньше**.
Поэтому вводить курс на каждый день не нужно — вносите его при изменении, и все даты между
будут использовать последний введённый.

Практическое следствие: **вносите курс на последний день месяца перед переоценкой валюты**
([§27](#27-чек-лист-закрытия-месяца), шаг 2). Без этого переоценка пойдёт по курсу, который
может быть недельной давности.

## 35. Разовый перенос из v4

**Это задача установки, а не пользователя.** Кнопки в программе для неё нет — она
запускается из командной строки один раз, когда бюро переходит на v5.

### Запуск

Из каталога `mizan5`, при остановленной программе:

```bash
python -m models.import_v4 ../mizan_finance.db
```

Аргумент — база v4. Если его не указать, ищется `../mizan_finance.db`.

База v4 **только читается**, никогда не изменяется. v4 продолжает работать.

### Что происходит

Копируются справочные данные — параметры, курсы, сотрудники, история зарплат, проекты,
этапы, табель, оборудование, лицензии, накладные, — а затем **каждая транзакция v4
проигрывается как настоящий документ v5 с настоящей проводкой**, в порядке дат.

Поскольку проигрывается вся история, начальные остатки не нужны, и денежные средства обеих
систем обязаны совпасть по построению.

Оборудование классифицируется на входе по ключевым словам, и каждое предположение
печатается для проверки.

### Как читать отчёт

Команда печатает сверку. Проверьте четыре вещи:

| Строка | Что должно быть |
|---|---|
| `cash_diff` | Практически ноль. Деньги v5 совпадают с расчётными деньгами v4. |
| `receivable_diff` | Ноль. Сальдо 4010 совпадает с непогашенной дебиторкой v4. |
| `trial_balance_ok` | True |
| `unbalanced_entries` | 0 |

Также печатается:

- **Пропущенные строки** с причиной. Они всегда сообщаются и никогда не отбрасываются
  молча. На реальной базе бюро было пропущено 2 транзакции из 1 028, обе действительно
  пустые.
- **Назначенные классы активов** по классам, со списком строк, не подошедших ни под одно
  правило и требующих решения человека.

### После переноса

1. Просмотрите пропущенные строки и введите вручную то, что имело значение.
2. Просмотрите классы активов на `/staff/equipment` и поправьте не распознанные.
3. Проверьте, что `/trial-balance` сходится и `/rates` даёт разумные цифры.
4. Задайте реальные сроки службы, если 36 месяцев везде — не то, что нужно бюро
   ([§22](#22-оборудование-классы-активов-лицензии-накладные)).

Не запускайте перенос дважды в одну и ту же базу.

## 36. Резервное копирование

Всё в одном файле: **`mizan5.db`**.

### Копирование

Остановите программу (`Ctrl+C`), скопируйте файл в другое место, запустите снова. Это вся
процедура.

```bash
copy mizan5.db backups\mizan5-2026-09-04.db
```

Копирование на ходу обычно срабатывает, но не гарантировано: копия, снятая посреди записи,
может оказаться несогласованной. Остановка занимает две секунды — сделайте это.

**Делайте копию как минимум раз в месяц и обязательно перед закрытием периода и перед
переносом из v4.**

### Восстановление

Остановите программу, замените `mizan5.db` резервной копией, запустите снова. Всё вернётся
к состоянию копии — частичного восстановления не бывает.

### Проверка на копии

Чтобы попробовать что-то без риска:

```bash
copy mizan5.db test.db
MIZAN5_DB=test.db PORT=5177 python app.py
```

Запустится второй, независимый экземпляр на копии. Ничто из сделанного там не затронет
рабочие данные.

### Что не входит в базу

Рядом лежат два файла, которые стоит сохранить: `.mizan5_secret_key` (его удаление
разлогинит всех, но не более) и `.env`, если вы его создавали.

## 38. Когда два числа не сходятся

### Панель сообщает, что учёт не сходится

> *ВНИМАНИЕ: дебет и кредит не равны!*

Откройте `/trial-balance` и посмотрите итоги. Поскольку программа отказывается проводить
несбалансированную проводку, это почти всегда следствие прямой правки базы или прерванного
переноса. Восстановите последнюю хорошую резервную копию
([§36](#36-резервное-копирование)).

### Баланс не сходится

Та же причина и тот же первый шаг: `/trial-balance`. Если оборотно-сальдовая ведомость
сходится, а баланс нет — у какого-то счёта неверный **Вид**, чаще всего пассивный счёт
создан как активный. Проверьте недавно добавленные счета на `/accounts`.

### Деньги на панели не совпадают с отчётом о движении денег

Эти три величины всегда должны быть равны: плитка денежных средств на панели, сумма сальдо
счетов 5xxx и конечный остаток в `/reports/cashflow`. Если нет — проверьте, не сужен ли
период в отчёте сильнее, чем вы думаете.

### Счёт числится неоплаченным, хотя заказчик заплатил

Платёж введён, но не **распределён** на этот счёт — скорее всего, он лежит на 6310 как
аванс. Откройте документ платежа и распределите его ([§13](#13-поступление-денег)).

### Ставки подскочили, хотя зарплаты никто не менял

В порядке убывания вероятности:

1. **Источник накладных переключился на таблицу.** Проверьте предупреждение на `/rates` и
   откройте `/rates/overhead` ([§24](#24-сверка-накладных-расходов)).
2. **У счёта изменили группу затрат.** Проверьте, что 9420.1/.2/.3 по-прежнему
   «Не учитывается» ([§9](#9-правило-двойного-счёта)).
3. **Крупный расход попал на 9420.** Теперь он распределён на всех. Исправьте, если он
   должен был быть затратами проекта или капитализирован.
4. **Изменились оплачиваемые часы.** На базе распределения по часам новые записи табеля
   двигают доли у всех.

### `/rates` предупреждает о некапитализированном оборудовании

Оборудование было списано на 9420 по счёту-фактуре, при этом оно есть и в регистре, — то
есть его стоимость попадает в ставки дважды. Исправление: указывать в таких строках счёт
0150 (или нужный счёт актива) — см. [§14](#14-счёт-фактура-полученный).

### У актива значок «Отличается»

Его срок службы отличается от классового. Это информация, а не ошибка: значок существует
именно для того, чтобы расхождение было видно. Изменение срока по классу никогда не меняет
уже записанный актив ([§22](#22-оборудование-классы-активов-лицензии-накладные)).

### У проекта значок «План изменился — зафиксируйте заново»

Живой план по этапам ушёл от зафиксированной базы. Решите осознанно: зафиксировать заново,
приняв новый план за базу, или оставить как есть, продолжая измерять относительно исходного
обязательства ([§25](#25-проекты-и-лестница-цен)).

### У сотрудника вообще нет себестоимости часа

У него нет записи о зарплате. Программа показывает *Зарплата не задана*, а не ноль, потому
что ноль тихо занижал бы каждый проект, над которым он работал. Добавьте зарплату на
`/staff` ([§21](#21-реестр-сотрудников-и-история-зарплат)).

### Пул накладных отрицательный

На 9430 попал доход. Откройте карточку счёта и посмотрите записи по кредиту — обычно это
поступление, введённое без контрагента ([§24](#24-сверка-накладных-расходов)).
